# خطّة بناء راصد ٣

> **للمنفّذ:** نفّذ المهامّ بالترتيب، وكل خطوة مربّع (`- [ ]`). المهارات: `test-driven-development` لكل مهمّة، `systematic-debugging` عند أيّ فشل، `verification-before-completion` قبل أيّ «تمّ».

**الهدف:** محرّك سحابيّ مجّانيّ يرصد كل قنوات جهات التدريب التعاونيّ، يصنّفها بذكاء مجّانيّ بأدلّة مقتبسة، وينبّه الشلّة، ثمّ تطبيق فضائيّ ثلاثيّ الأبعاد.

**البنية:** قطع صغيرة كل منها عمل واحد (جالب، مقارِن، مصنّف، طابور، مُرسل، ناشر). المحرّك يعمل في غيت هاب أكشنز كل ٣ ساعات، وحالته تُحفظ ملفّات في فرع `state` من المستودع (لا قاعدة بيانات). كل مصدر معزول؛ الفشل يُسجَّل ولا يُسقط غيره.

**الأدوات:** بايثون 3.12 (يُدار محلّيّاً بأداة `uv`)، `httpx`، `trafilatura` (استخراج نصّ الصفحة بلا اللافتات)، `hijridate` (أمّ القرى)، `pyyaml`، `pytest`، `respx` (محاكاة الشبكة في الاختبارات). تيليجرام عبر واجهته المباشرة. هيلث تشيكس للحارس.

**المرجع:** `SPEC.md` (خصوصاً §٤ §٥ §٧ §٨ والقسم ١١).

## قيود عامّة (تسري على كل مهمّة)

- كل الأوقات بتوقيت `Asia/Riyadh`. ساعات الهدوء 00:00–07:00؛ ما يُرصد فيها يُرسل 07:00.
- لا يُعلَّم مصدر «تمّ فحصه» إلّا بعد نجاح حقيقيّ.
- الفشل لا يحذف ولا يحسم شيئاً؛ يذهب لطابور إعادة ظاهر.
- كل حقل مستخرج معه `quote` (نصّ موجود حرفيّاً في المصدر) + `url` + `seen_at`. اقتباس غير موجود في المصدر = الحكم مرفوض.
- «مفتوح لكل التخصّصات» = مناسب.
- التنبيه يُعلَّم «أُرسل» فقط بإيصال (`message_id` من تيليجرام).
- لا بيانات شخصيّة في أيّ ناتج أو ملفّ مُلتزَم: لا إيميل، لا مسار جهاز، لا أسماء الحسابات الوهميّة. فحص آليّ يمنع الالتزام والنشر.
- المستودع **عامّ**: المفاتيح والكوكيز في الخزنة السرّيّة لغيت هاب فقط.
- رسائل الخطأ والسجلّات بالعربيّ وتسمّي القطعة والمصدر: `[الجالب][أرامكو/الموقع] فشل: ...`.
- نصوص التنبيه قوالب ثابتة؛ الذكاء يعبّئ خانات فقط.

## نقاط مراجعة لا تغطّيها الاختبارات العاديّة (أُضيفت اختباراتها لمهامّها)

1. صفحة تغيّر تصميمها كاملاً (كل الكتل «جديدة») ← لا سيل تنبيهات؛ تُرسل للمصنّف دفعة واحدة وتُحكم مرّة. (مهمّة ٤)
2. تاريخ هجريّ فقط بالأرقام العربيّة «١٥ جمادى الأولى ١٤٤٨» ← يتحوّل إلى 2026-10-26. (مهمّة ٣)
3. النموذج يرجع جواباً بشكل خاطئ أو اقتباساً مختلَقاً ← يُرفض ويُجرّب التالي، ولا يُخزَّن. (مهمّة ٦)
4. نفس البرنامج من الموقع وإكس بصياغتين ← بطاقة واحدة. (مهمّة ٨)
5. المحرّك ينهار وسط الجولة ← الحالة لا تُحفظ نصف محفوظة، والجولة التالية تعيد غير المكتمل. (مهمّة ١٠)

## شجرة المراحل

- **المرحلة ٠: تجهيز واختبار جدوى الذكاء** (مهامّ ١–٢) ← هذا الأسبوع
- **المرحلة ١: محرّك يرصد المواقع وينبّه على تيليجرام** (مهامّ ٣–١١) ← هدف: خلال أسبوعين
- **المرحلة ٢: إكس ولينكد إن** ← خطّة منفصلة بعد اختبار جدوى من السحابة (الحسابات الوهميّة تتعتّق ٢–٣ أسابيع أوّلاً)
- **المرحلة ٣: التقييم والنتائج المنشورة** (نجوم، نسبة المناسبة، التوقّع، تاريخ التفرّغ) ← خطّة منفصلة
- **المرحلة ٤: التطبيق** (قابل للتثبيت، تنبيهات فوريّة آيفون وأندرويد، زرّ «قدّمت»، زرّ التبليغ) ← خطّة منفصلة، تبدأ باختبار جدوى تنبيهات الآيفون
- **المرحلة ٥: التصميم الفضائيّ** (٣ نماذج حيّة ← اختيار ← ملفّ تصميم ← بناء) ← خطّة منفصلة
- **المرحلة ٦: القبول** (مراجع مستقلّ + ٤٨ ساعة تشغيل بلا تدخّل)

المراحل ٢–٥ لها خطط تفصيليّة تُكتب عند الوصول لها، لأنّ تفاصيلها تعتمد على نتائج اختبارات الجدوى.
